# Лабораторна робота №2. Розробка консольних утиліт для задач кібербезпеки

**Варіант 3** — Валідатор та аналізатор конфігурацій правил фаєрвола.

- **Завдання 1** (`task1.py`, демонстрація `main.py demo`): класи `User`, `Admin`, `Session`, `AuditLog`, `UserAccount`.
- **Завдання 2** (`task2.py`, команда `main.py analyze`): аудит правил фаєрвола з JSON/CSV.

Python **3.11+** (використовується `datetime.UTC`). Усі команди — з кореня репозиторію, в активованому віртуальному середовищі з ЛР №1:

```bash
pip install -r requirements.txt   # у файлі має бути рядок: ruff
```

## Вхідні дані

Файл: `labs/lab02/data/data_v03/firewall_rules.json` — масив із 14 правил. Кожне правило має поля:

| Поле | Значення |
|---|---|
| `id` | номер правила |
| `source` | IPv4 або підмережа `a.b.c.d/mask` (маска 0–32), або `ANY` |
| `destination` | IPv4 або підмережа, або `ANY` |
| `port` | число 1–65535 або `ANY` (у файлі рядком) |
| `action` | `ALLOW` або `DENY` (регістр не важливий) |

Також приймається CSV із заголовком `id,source,destination,port,action` (допустимі назви стовпців `Source IP`, `Destination IP`).

## Запуск

Демонстрація Завдання 1:

```bash
python -m labs.lab02.main demo
```

Аудит правил фаєрвола:

```bash
python -m labs.lab02.main analyze \
    --rules-file labs/lab02/data/data_v03/firewall_rules.json \
    --output labs/lab02/data/fw_audit_report.json \
    --check-conflicts \
    --log-level INFO
```

PowerShell: замість `\` в кінці рядка використовуйте зворотний апостроф `` ` `` або запишіть команду в один рядок.

Довідка: `python -m labs.lab02.main analyze --help`.

## Параметри `analyze`

| Параметр | Обов'язковий | Опис |
|---|---|---|
| `--rules-file` | так | Шлях до файлу правил (`.json` або `.csv`). |
| `--output` | ні | JSON-звіт аудиту. За замовчуванням `fw_audit_report.json` поруч із файлом правил. |
| `--check-conflicts` | ні | Прапорець: додатково шукати суперечливі правила (ALLOW і DENY для того самого потоку). Без нього виконуються валідація, пошук дублікатів і небезпечних правил. |
| `--log-level` | ні | `DEBUG`, `INFO` (типово), `WARNING`, `ERROR`, `CRITICAL`. Керує тим, які повідомлення і знахідки виводяться. |
| `--cleaned-output` | ні | Файл очищеного списку правил. За замовчуванням `<output>_cleaned_rules.json`. |
| `--log-file` | ні | Додатково записувати журнал у файл (із часовими мітками). |

## Що перевіряє утиліта

1. **Валідація** (регулярні вирази `re`): IPv4-октети 0–255, маска 0–32, порт 1–65535 або `ANY`, дія `ALLOW`/`DENY`. Некоректні правила потрапляють у звіт і виключаються з подальшого аналізу.
2. **Дублікати**: правила з однаковими (джерело, призначення, порт, дія), групування через `collections.defaultdict`. Залишається перше правило.
3. **Суперечності** (`--check-conflicts`): той самий потік (джерело, призначення, порт) має і `ALLOW`, і `DENY`. Адреси нормалізуються через `ipaddress` (`10.0.0.5` = `10.0.0.5/32`).
4. **Небезпечні правила**: `ALLOW` із джерелом `0.0.0.0/0` та/або портом `ANY`. Для відкритих в Інтернет `22`, `23`, `21`, `3389` додається позначка сервісу.

## Результати

- Консольний звіт і знахідки (`[INVALID]`, `[DUPLICATE]`, `[CONFLICT]`, `[HIGH-RISK]`).
- `--output` — JSON: `summary` (лічильники) і `findings` (деталі).
- `<output>_cleaned_rules.json` — очищений список у тому самому форматі, що й вхідний (можна подати назад в утиліту). Із нього прибрано некоректні правила та дублікати. Суперечливі правила **залишаються**: рішення, яке з них видалити, приймає адміністратор.

## Поведінка при помилках

| Ситуація | Результат |
|---|---|
| Файл правил не знайдено, непідтримуваний формат, некоректний JSON/CSV | `[ERROR]` у журналі, код завершення `1` |
| Не вдалося записати звіт або журнал | `[ERROR]`, код `1` |
| `--output` або `--cleaned-output` збігається з вхідним файлом | Відмова, вхідний файл не перезаписується, код `1` |
| Недопустиме значення `--log-level` | Повідомлення `argparse`, код `2` |
| Некоректні значення всередині правил | Не є помилкою програми: правила потрапляють у звіт, код `0` |

## Безпека (Завдання 1)

- Пароль зберігається лише як `PBKDF2-HMAC-SHA256` (600 000 ітерацій) з випадковою сіллю 16 байт (`os.urandom`), порівняння через `hmac.compare_digest`.
- Хеш і сіль — приватні атрибути (`__password_hash`, `__password_salt`), через `account[...]` недоступні.
- Журнал аудиту приймає лише коди дій (`login_success`, `login_failure`, `logout`, `session_timeout`), тому пароль у нього потрапити не може.
- Усі навчальні облікові дані в `demo` вигадані.
